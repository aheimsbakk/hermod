Added an explicit tuple-length guard in `_query_one` (`src/hermod/network/stun.py`)
immediately after `getaddrinfo` returns: if `stun_addr` is not a plain 2-tuple
(e.g. an IPv6 4-tuple `(addr, port, flow, scope)`), the query is skipped with a
DEBUG log instead of propagating to `transport.sendto`, which would cause asyncio to
log `"Fatal write error on datagram transport"` at ERROR level. This is defense-in-depth
on top of the `family=AF_INET` constraint added in v0.3.4. Bumped to v0.3.5.
